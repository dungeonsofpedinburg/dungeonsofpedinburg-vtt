# React + TypeScript + Vite

This template provides a minimal setup to get React working in Vite with HMR and some Oxlint rules.

Currently, two official plugins are available:

- [@vitejs/plugin-react](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react) uses [Oxc](https://oxc.rs)
- [@vitejs/plugin-react-swc](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react-swc) uses [SWC](https://swc.rs/)

## React Compiler

The React Compiler is not enabled on this template because of its impact on dev & build performances. To add it, see [this documentation](https://react.dev/learn/react-compiler/installation).

## Expanding the Oxlint configuration

If you are developing a production application, we recommend enabling type-aware lint rules by installing `oxlint-tsgolint` and editing `.oxlintrc.json`:

```json
{
  "$schema": "./node_modules/oxlint/configuration_schema.json",
  "plugins": ["react", "typescript", "oxc"],
  "options": {
    "typeAware": true
  },
  "rules": {
    "react/rules-of-hooks": "error",
    "react/only-export-components": ["warn", { "allowConstantExport": true }]
  }
}
```

See the [Oxlint rules documentation](https://oxc.rs/docs/guide/usage/linter/rules) for the full list of rules and categories.

## Локальный запуск

```bash
npm install
npm run dev       # Vite (5173) + sync-сервер (5174) в одном окне
```

`npm run dev` поднимает всё, что нужно для работы: и интерфейс, и связь окон, и
сохранение файлов выпуска на диск. Исторический псевдоним `npm run dev:all`
делает то же самое, а `start_windows.bat` / `start_mac.command` просто вызывают
`npm run dev` — отдельных команд для загрузки картинок, музыки и видео не нужно.

* Мастер-панель — http://localhost:5173/master
* Экран для OBS — http://localhost:5173/screen (источник «Браузер»)
* Связь окон — локальный WebSocket-сервер на порту 5174 (`server/index.mjs`)

OBS Browser Source живёт в отдельном процессе CEF, поэтому `BroadcastChannel`
между окном мастера и источником не работает. Состояние выпуска идёт через
WebSocket: сервер держит последний снапшот в памяти и отдаёт его тому, кто
подключился позже — например, только что перезагруженному источнику в OBS.

Отдельные команды, если нужен только один процесс:

```bash
npm run dev          # Vite + sync-сервер (то же, что dev:all)
npm run dev:all      # псевдоним предыдущей команды
npm run sync         # только sync-сервер
npm run preview      # собранная сборка + sync-сервер
```

### Адреса и флаги

* `http://localhost:5174/health` — состояние сервера: есть ли снапшот, кто подключён;
* `?sync=ws://192.168.1.5:5174` — адрес сервера вручную (если OBS на другой машине);
* `VITE_SYNC_URL=ws://10.0.0.7:5174` — адрес для собранной сборки;
* `?badge=always` / `?badge=off` — индикатор связи на /screen: показывать всегда или выключить
  (по умолчанию виден, пока связи нет, и гаснет через несколько секунд после подключения);
* `SYNC_PORT`, `SYNC_HOST`, `WEB_PORT` — переопределение портов и адреса прослушивания.

## Папка assets: папки выпусков и кэш вне Git

Корневая папка `assets/` разделена на две строгие зоны:

* **`assets/episodes/<slug>/`** — выпуск целиком: `episode.json` (или одноимённый
  `<slug>.json` рядом), подпапки `scenes/`, `characters/`, `items/`, `music/`,
  `soundpad/`, `videos/`. Сюда пишет **экспорт**: он выгружает встроенные
  картинки, музыку и видео прямо в папку своего выпуска, поэтому её можно целиком
  заархивировать и передать. `<slug>` — безопасный идентификатор из названия
  выпуска (`generateEpisodeSlug`: «Порт в тумане» → `port-v-tumane`), он же виден
  бейджем в шапке Мастер-панели.
* **`assets/cache/`** — временный кэш и наследие: сюда попадают только запросы
  выгрузки с коротким путём (`scenes/...`) и файлы старых черновиков. Папку можно
  стереть целиком — приложение создаст её заново, если такой запрос придёт.

Картинки предметов (4-я колонка «Предметы», `category: "item"`) едут в `items/`,
а не в `characters/`: папка выбирается по категории в `characterAssetFolder`
(`src/lib/export-episode.ts`).

В репозиторий не попадает ни то, ни другое: в `.gitignore` стоят
`assets/episodes/*` и `assets/cache/*` (пустые каталоги переживают клонирование
благодаря `.gitkeep`, гигабайты видео — нет). Системные ассеты проекта
(плейсхолдеры и раздача кубиков) лежат в `public/` и не затрагиваются.

Старые пути работают без сбоев: запрос `/assets/scenes/...` сервер ищет в кэше, а
запрос `/assets/cache/...` (черновик, собранный до изоляции выпусков) — сначала в
кэше, затем запасным поиском по папкам `assets/episodes/**`: сначала точное
совпадение `<выпуск>/<тот же путь>`, потом по имени файла. Если файла нет нигде,
запрос уходит дальше по стеку Vite (в dev это страница приложения, а не файл).

## Проверки проекта

```bash
npm run lint    # oxlint
npm run build   # tsc -b && vite build
npm run smoke   # смоук-тесты стора и хелперов (src/store/syncSmoke.ts) в Node
```

`npm run smoke` поднимает Vite в SSR-режиме и sync-сервер на свободном порту,
затем прогоняет проверки из `src/store/syncSmoke.ts`: стор выпуска, связка
мастера и `/screen` через сокеты (кэш состояния, presence, переподключение),
экспорт/импорт, slug выпуска, разделители сцен, саундтрек, геометрия сетки и
размер кубиков. Вторая фаза (`scripts/smoke-assets.mjs`) поднимает настоящий
HTTP-сервер Vite и проверяет раздачу и выгрузку: кириллица, пробелы и «№» в пути,
имена в форме NFD (macOS), Range-запросы, папку предметов `items/`, запись ассетов
в `assets/episodes/<slug>/<папка>/`, запасной поиск старого пути `/assets/cache/...`
и отсечение выхода за папку, чужого slug и чужого расширения.

## Выпуск: JSON + папка выпуска

Файл выпуска (`episodeSlug.json`) весит десятки-сотни килобайт: в нём только
текст — заметки актов (`groupNotes`), музыка актов (`groupTracks`), координаты
токенов 15×6, поле `episodeSlug` и относительные пути к ассетам
(`/assets/episodes/port-v-tumane/scenes/forest.jpg`).
Base64 (`data:...`) в JSON не пишется никогда: картинки и музыка лежат отдельными
файлами в папке выпуска.

* **Экспорт** («Экспортировать выпуск») выгружает выбранные в панели картинки и
  треки через локальный сервер (`vite.config.ts`, плагин
  `pedinburg:serve-episode-assets`, POST `/__pedinburg/assets`) в папку выпуска
  `assets/episodes/<slug>/` и только потом собирает JSON. Имя файла — `id` + слаг
  названия (`/assets/episodes/port-v-tumane/scenes/bg-harbor-порт-в-тумане.jpg`),
  поэтому повторный экспорт перезаписывает те же файлы, а не копит копии.
  Предметы (`category: "item"`) уезжают в `items/`, персонажи — в `characters/`,
  видео-сцены — в `videos/` (они грузятся в папку выпуска сразу, ещё при
  добавлении сцены).
* **Передача**: Продюсер сжимает папку `assets/episodes/<slug>/` в `<slug>.zip` и
  отправляет Мастеру вместе с файлом `<slug>.json`. Мастер распаковывает архив в
  `assets/episodes/` и импортирует JSON — всё на месте, потому что папка, файл и
  пути внутри JSON называются одним slug. Диалог экспорта показывает эту памятку.
* **Импорт** берёт `episodeSlug` из файла (в старых файлах поля нет — slug
  выводится из названия выпуска), а пути приводит к виду `/assets/...` (буквы
  диска, `file://`, обратные слеши и домашние папки `/Users/...` уходят), имена из
  macOS переводит из NFD в NFC. Если локального сервера нет (сборка раздаётся
  статикой), встроенный Base64 из старого файла в JSON не вернётся — поле
  останется пустым, а причина попадёт в отчёт экспорта.
* **Импорт** приводит чужие пути к виду `/assets/...` (буквы диска, `file://`,
  обратные слеши и домашние папки `/Users/...` уходят), а имена из macOS
  переводит из NFD в NFC. Если локального сервера нет (сборка раздаётся
  статикой), встроенный Base64 из старого файла в JSON не вернётся — поле
  останется пустым, а причина попадёт в отчёт экспорта.

## Видео-сцены и плеер Мастера

Сценой может быть не только картинка, но и видео (`.mp4`, `.webm`): файл
выбирается там же, где картинка («+» в разделителе или двойной клик по сцене —
`accept="image/*,video/mp4,video/webm"`).

* Видео сразу выгружается в папку выпуска `assets/episodes/<slug>/videos`
  (`src/lib/video-file.ts` и эндпоинт
  `POST /__pedinburg/assets`), поэтому в снапшот для `/screen` уезжает короткий
  путь, а не десятки мегабайт Base64. Предел одного файла — **1 ГБ на тело
  запроса** (в JSON ассет едет в base64, это ещё +33 % к размеру), поэтому
  тяжёлые видео-фоны в 70–500 МБ загружаются без ограничений; что больше —
  сервер честно отвечает `413` с причиной.
* Тип сцены определяется по расширению (`isVideoSrc`), поэтому `SceneStage`
  рисует `<video autoPlay playsInline muted object-cover>` вместо `<img>` —
  одинаково в панели Мастера и на `/screen`. `muted` обязателен: фон не должен
  перебивать саундтрек.
* Внизу Viewport Мастера выезжает плеер: он спрятан, пока курсор вне сцены, и
  появляется при наведении (`group-hover`/`focus-within`). Внутри — пауза,
  скруббер с таймкодом `00:14 / 01:30` и кнопка повтора (`Repeat`, включённый
  цикл подсвечен `text-amber-400`). Перемотка работает благодаря Range-запросам
  (`206 Partial Content`) в раздаче `assets/`.
* **Управление общее на два окна:** пауза, повтор и перемотка лежат в сторе
  (`videoPlayback`) и уезжают на `/screen` снапшотом синхронизации, поэтому
  проектор останавливается вместе с превью. Оба окна применяют команды одним и
  тем же кодом в `SceneStage`; перемотка отправляется один раз — на отпускании
  ползунка (`seekId` — метка события).
* Флаг зацикливания хранится и в живом состоянии (для `/screen`), и в самой сцене
  (`Background.isLoop`, по умолчанию `true`), поэтому выбор Мастера переживает
  возврат на сцену и уезжает в файл выпуска.

## Множественное удаление

Для персонажей и сцен работает режим выделения: ПКМ по элементу →
**«Выделить несколько»**. В секции появляются чекбоксы и плашка «Выбрано: N» с
кнопками «Удалить выбранные» и «Отмена», клик по элементу переключает его
отметку, а `Delete`/`Backspace` удаляют выбранное (в полях ввода и в редакторе
заметок клавиши работают как обычно — см. `isTextEntryTarget`). Выход из
режима — `Escape`, «Отмена» или удаление.

Логика удаления живёт в сторе (`deleteBatchCharacters`, `deleteBatchBackgrounds`,
`deleteBatchTracks`, `deleteBatchSoundpadSlots`): персонажи уходят со сцены и с
карт вместе со своими токенами, сцены — с раскладкой токенов, а выпуск не может
остаться без сцен. Заметки и музыка привязаны к группам сцен (актам), поэтому
удаление сцен их не затрагивает. В узкой аудио-панели треки и звуки удаляются по
одному через контекстное меню — пачечные действия стора там не нужны.

## Заметки и музыка актов

Заметки мастера пишутся **на группу сцен (акт)**, а не на отдельную сцену: акт —
единица подготовки выпуска. Слева во вкладке «Описание сцен» — узкая колонка
актов (5% ширины окна, как и колонка карт рядом), справа — редактор заметки
выбранного акта: имя правится инлайн, текст уезжает в `groupNotes`
(`updateGroupNote`), рядом видно число сцен и привязанную музыку. Заметки попадают
в файл выпуска как `groupNotes`; файлы старого формата (`sceneNotes` по сценам)
при импорте переносятся на акты своих сцен.

Музыку акта привязывают прямо на разделителе в библиотеке слева: кнопка с иконкой
`Music` («+») открывает выбор аудиофайла, файл сразу уезжает в папку выпуска
(`assets/episodes/<slug>/music/`), а в стор ложится путь (`groupTracks`). ПКМ по
кнопке — «Заменить трек» / «Удалить трек»; когда у акта есть музыка, иконка
подсвечена `text-primary`, а название трека видно в тултипе.

Аудио-движок (`useSoundtrackPlayer` + `src/lib/group-track.ts`) ведёт музыку актов
по правилам:

* **внутри одного акта** трек не меняется и не перезапускается — переключение сцен
  музыку не трогает;
* **переход в другой акт с треком** — кроссфейд: старый затухает (~1.5 с), новый
  проявляется;
* **переход в акт без трека** — музыка предыдущего акта продолжает играть;
* **ручной трек из правой панели** перекрывает музыку акта: она запоминает свою
  позицию и ставится на паузу, а на паузе ручного трека возвращается ровно с того
  же места (`savedCurrentTime`) и плавно нарастает.

Решения движка вынесены в чистые функции `resolveGroupTrackAction` и
`shouldResumeGroupTrack` — их проверяет смоук-прогон, а сам хук только исполняет
решение (в Node нет ни браузера, ни `HTMLAudioElement`).


## Чистый старт: пустой выпуск

Приложение (и кнопка «Создать новый выпуск») стартует с абсолютно пустым
выпуском: ни сцен, ни персонажей, ни треков, ни звуков, ни токенов —
`src/data/seed.ts` держит только пустые наборы и `backgroundIcon`, демо-данных
там нет. Активная сцена (`activeBackgroundId`) и карта (`activeMapId`) равны
`null`, поэтому сцена показывает подсказку «Сцена не выбрана», библиотека сцен —
«Выпуск пока пуст: сцен нет», а вкладка карт — «Нет карт местности». Пустой
выпуск корректно проходит экспорт и импорт: файл без сцен больше не считается
ошибкой.

## Вкладки Мастер-панели и глобальная аудио-панель

Главный экран занимает всю ширину окна: внешние поля слева и справа — ровно 1%
(`px-[1vw]`), а сам экран делится на три колонки (перетаскиваемые разделители):

1. **Слева (35%)** — превью сцены, панель токенов и библиотека сцен.
2. **По центру (57%)** — вкладки: «Описание сцен» (1), «Карты местности» (2),
   «Кубики» (3). Клавиши `1`–`3` переключают вкладки. У каждой вкладки со списком
   (заметки актов, карты местности) левая колонка выбора занимает **5% ширины
   окна** (`w-[5vw]`), чтобы обе вкладки выглядели одинаково.
3. **Справа (8%, минимум 85 px)** — глобальная аудио-панель
   (`GlobalAudioSidebar`): она видна при любой вкладке, поэтому музыка и эффекты
   всегда под рукой. Отделена вертикальным дивайдером.

Карты местности: список карт — узкая колонка **внутри вкладки**, ровно 5% ширины
окна (`w-[5vw]`): компактные квадратные миниатюры с названием в одну строку и
счётчиком токенов, выбранная карта подсвечена `ring-2 ring-primary`. Справа —
сетка 15×6 и четыре колонки категорий токенов под ней. Раньше карты
переключались горизонтальной полосой сверху — её больше нет.

Аудио-панель состоит из двух секций одинаковых квадратных плиток и транспорта:

* **Звуки (саундпад):** плитка — иконка Lucide и название в одну строку
  (`truncate`), клик играет эффект, ПКМ → «Редактировать» / «Удалить»,
  «+» открывает диалог из набора `SOUNDPAD_ICON_NAMES` (`src/lib/soundpad.ts`).
  Эффекты играет `src/lib/sfx-player.ts`: у каждого звука свой `new Audio(src)`,
  он не трогает деки плеера и не глохнет вместе с музыкой.
* **Музыка (треки):** такие же квадратные плитки с обложкой (`coverSrc`) или
  иконкой `Music`, играющий трек подсвечен пульсирующей рамкой. Клик включает
  трек с кроссфейдом (повторный клик — пауза), «+» сразу открывает проводник и
  читает метаданные MP3, ПКМ → «Редактировать» / «Удалить», плитки
  перетаскиваются для сортировки плейлиста.
* **Транспорт внизу:** предыдущий/следующий трек, пуск-пауза, режим повтора,
  громкость и название текущего трека. Плеер живёт в `SoundtrackProvider` над
  панелями, поэтому переключение вкладок музыку не обрывает.

Слоты саундпада и треки входят в файл выпуска: при экспорте файлы ложатся в
`assets/episodes/<slug>/soundpad/` и `assets/episodes/<slug>/music/`, а в JSON
уезжает только путь. `/screen` ни музыку, ни эффекты не транслирует: звук
остаётся в панели Мастера.
